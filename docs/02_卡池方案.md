## 设计原则

1. 每等级 6 张、同等级内等概率出现（抽卡引擎先判等级再在该等级内均匀选卡）。
2. emoji 仅装饰：卡面主体是「卡名 + 等级色边框 + 描述」，规避 Windows/移动端 emoji 渲染差异（架构文档 R1 风险）。
3. `image` 字段全部留空，未来 ComfyUI 出图直接填路径，无表结构迁移。
4. 文案梯度：SSR/传说 = 可望不可即的幸存者神话；史诗 = 惊险但人定胜天；稀有 = 日常小确幸；普通 = 自嘲与噪音。等级越高越接近传说，符合收集心理。
5. 涉及具体数字（47 次、三年、凌晨三点）是有意为之——具体数字比「很多次」更有真实感。

## 卡池扩展机制（用户 2026-10-28 确认：预留后续加卡空间）

后续添加新卡**零迁移、零改动**，四层保障：

1. **表结构层**：`cards.id` 为 AUTOINCREMENT，新卡自动拿新 id；编号 1~30 只是「第一批种子卡」，新卡从 31 起，不复用、不重排旧号。`collections` / `draws` 都按 `card_id` 关联，新卡天然进池。
2. **种子层**：`seed_cards.py` 用 `INSERT OR IGNORE`（以 `name` 唯一键判重）——脚本反复跑不产生重复卡，也不会覆盖数据库里人工改过的卡；追加新批次卡只需在 `CARDS` 列表末尾续写元组。
3. **后台层**：迭代 3 的管理员后台支持直接增卡（表单提交即入库生效）与软下架（`enabled=0`，不出新但不破坏历史流水与已收集关系）。
4. **数量层**：每级 6 张只是首批的均匀分布，后续不要求「凑满 6 的倍数」——抽卡引擎先判等级再在该等级已启用的卡中均匀选，每级 1 张也照常工作。若某等级被下架到 0 张，后台保存概率时校验并拒绝（防抽卡引擎空选）。

## ComfyUI 卡面预览（2026-10-28 实测）

- 本机 SD1.5（`v1-5-pruned-emaonly.safetensors`）单张出图成功：768×512 / euler / cfg 7.5 / 28 步，耗时约 85 秒；三层校验通过（518KB / PNG 魔数 / 像素方差 3621），人工抽查无畸形、无乱码、无水印。
- 预览图为「重启就好了」SSR 概念（金光氛围空景，无人物无文字），产物：`E:\workbuddy\2026-10-28-gacha-preview\gacha_ssr_preview_00001_.png`。
- 结论：**SD1.5 适合做「氛围底图型」卡面**（等级色 + 光效背景 + 卡名/emoji 前景排版）；出图走「全空景、无人物」路线规避手脸崩坏。若需要具象主体（机柜/物件），需调整提示词重点强化主体词再试。
- 批量产卡建议沿用手册策略：每 2~3 张重启一次服务防 DirectML 状态劣化；中文卡名一律由前端排版叠加，不指望模型写字。
