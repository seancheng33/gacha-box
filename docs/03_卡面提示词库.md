| 项目 | 内容 |
|------|------|
| 版本 | v1.0 |
| 日期 | 2026-10-30 |
| 用途 | 供任意 AI 出图工具（Midjourney / SD WebUI / ComfyUI / 即梦 / DALL·E 等）复用的正负提示词 |
| 上游文档 | 02_卡池方案.md（卡名/等级/文案）、01_架构与系统分析.md（等级体系） |

> **这份文档是「通用提示词」**，不绑定任何一家工具。SD 系（WebUI/ComfyUI）直接按下面的「正向 / 负向」两段复制即可；Midjourney 把负向词改写成 `--no` 参数（文末给了对照表）；即梦/DALL·E 这类自然语言工具，把正向段当作场景描述、负向段当作「避免出现」清单来填。

---

## 一、先约定三件事（避免出图白忙）

1. **卡片是竖版**，比例约 **2:3**（游戏里卡面渲染宽 132px，高按图片自然比例）。
   - SD/ComfyUI 推荐分辨率：**512×768**（SD1.5）/ **768×1152**（SDXL）
   - Midjourney 加 `--ar 2:3`；即梦/通义等选「竖版」
2. **画面里不要出现任何文字**（尤其是中文和伪字母）。卡名、等级、描述全部由前端排版叠加在卡面之上，AI 只管出「背景氛围图」。
3. **卡面分「正面」和「背面」两种**，用途不同：
   - **正面** = 每张卡独一无二的「主视觉」（对应 02 文档里 30 张卡各自的主题）
   - **背面** = 未抽到 / 未收集时显示的「统一卡背」，全游戏只用一张

---

## 二、通用负向提示词（所有卡共用，直接整段复制）

> 负向词是「画面里绝对不能出现」的东西，写全一点能省很多返工。下面这段可以直接用于 SD 系（WebUI / ComfyUI）：

```
lowres, worst quality, low quality, blurry, jpeg artifacts, watermark,
signature, text, letters, words, logo, chinese character, chinese text,
bad anatomy, bad hands, extra fingers, deformed, mutation, extra limbs,
out of frame, cropped, duplicate, nsfw, nude,
oversaturated, overexposed, harsh light, flat color, solid background,
frame, border, card border, ui element, game ui, icon, interface,
photorealistic, photo, realistic photo, 3d render, cg render, cartoon face,
anime face, person, people, human, character, portrait, face, hand, finger
```

**逐条说明（便于你按工具裁剪）：**

| 分组 | 词 | 为什么要排除 |
|------|----|------|
| 画质 | `lowres, worst quality, blurry, jpeg artifacts` | 出图最低画质红线 |
| 水印文字 | `watermark, signature, text, logo, chinese character` | 卡面不能有字，尤其中文必乱码 |
| 身体畸形 | `bad hands, extra fingers, deformed, mutation` | 抽卡图里手和脸是最容易崩的，直接不让画人 |
| 画面裁切 | `out of frame, cropped, duplicate, frame, card border, ui element` | 卡面要干净无边框，UI 由前端做 |
| 风格冲突 | `photorealistic, photo, 3d render, cartoon face, anime face, person, human` | 我们走「插画氛围空景」，不要真人感、不要人物 |
| 光线 | `oversaturated, overexposed, harsh light, flat color, solid background` | 避免过曝和纯色死背景 |

## 四、背面卡面（统一一张，全游戏共用）

卡背是「未收集」状态的占位视觉，做一张即可，无需分等级。设计取向：**神秘、统一、与主题呼应**——深色底、中央一个金色问号或盒体图腾、放射状纹样，暗示「尚未揭晓」。

**正向提示词：**

```
masterpiece, best quality, highly detailed, illustration, game card back,
dark navy background, mysterious, a golden glowing question mark emblem
in the center, ornate geometric border pattern, radial glow,
subtle particle dust, elegant, premium collectible card,
no text, no letters, no logo, no people, centered composition,
vertical composition, 2:3
```

**负向提示词：** 复制第二节整段，再追加下面这几条（针对卡背）：

```
bright background, white background, colorful, busy, cluttered, words, text
```

## 五、Midjourney 负向词对照（--no 写法）

SD 的负向段在 Midjourney 里改用 `--no` 参数。正向段基本可以原样当 prompt，负向段这样转：

```
--no text, letters, words, logo, watermark, signature, chinese characters,
person, people, human, face, hand, fingers, photorealistic, photo, 3d render,
frame, border, ui, interface, nsfw
```

再加比例和版本：`--ar 2:3 --style raw`（`raw` 弱化 Midjourney 自带的美颜滤镜，更接近你要的干净插画）。

## 六、快速取用速查（一张纸能贴完）

- **通用负向**：第二节整段，一字不改，所有卡都贴。
- **正面** = 第三节 3.1 选等级前缀 + 3.2 选主题词，套进 3.3 模板。
- **背面** = 第四节正向，负向 = 通用负向 + 卡背追加四条。
- **出图尺寸**：SD1.5 用 512×768；SDXL 用 768×1152；MJ 加 `--ar 2:3`。
- **关键红线**：全程 `no text / no people / no hands`，卡面干净，文字和人物都交给前端。

## 七、实测结论（2026-10-30，本机 AMD RX 590 / DirectML）

> 结论先行：**本机 AI 出图做不出这套卡面，最终改用 `tools/make_cards.py`（HTML+CSS+SVG 合成）**。下面是 8 次实测的记录，供你在别的机器/云端出图时参考。

### 7.1 结果统计

| 模型 | 尺寸 | 尝试 | 可用 | 主要问题 |
|------|------|------|------|----------|
| SD1.5 (`v1-5-pruned-emaonly`) | 512×768 | 4 | 0 | 画「电源按钮」→ 金色长发女神 / 纯金色光斑 / 抽象深色圆盘 |
| Illustrious-XL v2.0 | 768×1152 | 2 | 0 | NaN，全黑图 |
| Illustrious-XL v2.0 | 576×864 | 4 | 2 | 一张可用（金边按钮），一张跑偏（硬盘→纪念碑+荒野+子弹壳） |
| Illustrious-XL v2.0 | 512×768 | 1 | 0 | NaN，全黑图 |

### 7.2 四条硬约束（都是踩出来的）

1. **DirectML 只上报 1GB 显存**（日志 `Total VRAM 1024 MB`），8GB 物理显存用不上。
2. **SDXL 竖版面积上限约 50 万像素**（≈576×864）。更大即 NaN → 黑图，日志特征 `nodes.py:1699 RuntimeWarning: invalid value encountered in cast`。
3. **服务重启后第一张图几乎必黑**，第二张才正常（"预热"）。每次重启都要先浪费一张。
4. **部分种子确定性触发 NaN**，同参数换种子即好。同一提示词抽 2~3 次是正常成本。

### 7.3 提示词层面的教训

- `divine / sacred / holy / majestic / radiant rays / luminous particles` 这类强光效词会**吃掉主体**：画「圣光中的电源按钮」得到的是女神像。
- 修正方向：主体前置并加权 `(a power button:1.4)`、加 `still life, object photography` 锚定、光效改成 `golden rim lighting`（只打光、不发光）。
- **AI 画不了精确几何符号**（电源图标、勾选、进度条），它只会画「像个圆的东西」。
- 反向发现：把提示词写成「卡牌背景」时，模型会**自发画出卡框 + 星级 + 文字区**，说明它对「游戏卡牌」这一概念的理解远超对具体物件的理解。

### 7.4 为什么最终放弃 AI 出图

卡面有三条硬需求，AI 一条都满足不了：

1. **30 张风格绝对统一** → AI 每张都要重新抽，风格必然漂移。
2. **图形必须精确**（电源符号、回车键、STOP 标签）→ 模型只会近似。
3. **中文必须清晰无乱码** → 模型写字必废。

这三条恰好是程序化合成的强项，所以改用 HTML+CSS+手绘 SVG，一次生成 31 张，风格完全一致、零乱码、可随时改配色重跑。

本文件保留完整提示词，是因为它对你**在别的设备/云端出图**仍然有效——那边没有 1GB 显存限制，Illustrious/SDXL 可以跑 1024×1536，命中率会高得多。
